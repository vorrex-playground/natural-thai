# ตัวอย่าง Before / After

ไฟล์นี้รวมคู่เทียบ "ภาษา AI" กับ "ภาษาคนเขียน" ไว้ให้ดูเป็นแนวทาง
แบ่งตามสถานการณ์ที่เจอบ่อย ๆ พร้อมการเว้นวรรคและการสะกดคำทับศัพท์ที่ถูกต้องตามราชบัณฑิตยสภา

---

## 1. อธิบายเรื่องเทคนิค

### Docker

แบบที่ไม่ควรทำ :
> Docker เป็นแพลตฟอร์มโอเพนซอร์สที่ทำการจัดการ containerization ซึ่งมีบทบาทสำคัญอย่างยิ่งในภูมิทัศน์ของการพัฒนาซอฟต์แวร์สมัยใหม่ โดยทำให้นักพัฒนาสามารถดำเนินการแพ็กเกจแอปพลิเคชันพร้อมด้วย dependencies ทั้งหมดลงใน container ที่มีความเป็นเอกเทศ

แบบที่อ่านแล้วเข้าใจ :
> Docker ช่วยให้เราห่อแอปทั้งหมด ทั้งโค้ด ทั้งของที่โค้ดต้องใช้ ไว้ในกล่องเดียว เรียกว่า container
>
> เหมือนกล่องข้าวที่ใส่ทุกอย่างครบ เปิดกินได้เลย ไม่ต้องไปหาข้าว หาแกง หากับข้าวแยก เครื่องไหนเปิดกล่องนี้ก็ใช้ได้เหมือนกันหมด

*คำอธิบายศัพท์ : container คือ กล่องจำลองสภาพแวดล้อมที่รวมโค้ดและส่วนประกอบที่จำเป็นไว้ในที่เดียว*

---

### REST API

แบบที่ไม่ควรทำ :
> REST API (Representational State Transfer Application Programming Interface) เป็นรูปแบบสถาปัตยกรรมซอฟต์แวร์ที่ใช้โปรโตคอล HTTP ในการสื่อสารระหว่างไคลเอนต์และเซิร์ฟเวอร์ โดยมีการดำเนินการผ่านเมธอดต่าง ๆ อาทิ GET, POST, PUT และ DELETE

แบบที่อ่านแล้วเข้าใจ :
> API เหมือนพนักงานเสิร์ฟในร้านอาหาร เราสั่งอาหาร (ส่ง request) พนักงานไปบอกครัว (server) แล้วเอาอาหารกลับมาให้ (response)
>
> REST ก็คือ "กฎมารยาท" ของพนักงานนั่นแหละ จะสั่งดู (GET) เพิ่ม (POST) แก้ (PUT) หรือยกเลิก (DELETE) ก็ใช้คำสั่งที่ตกลงกันไว้

*คำอธิบายศัพท์ : API คือ ช่องทางเชื่อมต่อและแลกเปลี่ยนข้อมูลระหว่างโปรแกรมต่าง ๆ*

---

### Git

แบบที่ไม่ควรทำ :
> Version Control System (VCS) เป็นระบบที่มีความสำคัญอย่างยิ่งในการจัดการการเปลี่ยนแปลงของซอร์สโค้ด โดยดำเนินการบันทึกประวัติการแก้ไขทุกครั้ง ทำให้นักพัฒนาสามารถย้อนกลับไปยังเวอร์ชันก่อนหน้าได้

แบบที่อ่านแล้วเข้าใจ :
> Git เหมือน Save Point ในเกม เขียนโค้ดไปเรื่อย ๆ เซฟไว้เป็นจุด ๆ ถ้าพัง ก็กด Load กลับไปตอนที่ยังดีอยู่ได้
>
> แถมบอกได้ด้วยว่าใครแก้อะไร ตอนไหน ทำไมถึงแก้

*คำอธิบายศัพท์ : Version Control คือ ระบบบันทึกประวัติการแก้ไขโค้ด*

## 2. ตอบคำถาม แนะนำวิธีแก้ปัญหา และการสื่อสารในที่ทำงาน

### รายงานผลการแก้บั๊ก (สาย Dev)

แบบที่ไม่ควรทำ :
> จากการวิเคราะห์สาเหตุของปัญหาดังกล่าว พบว่าเกิดจากการที่ระบบไม่ได้กำหนดค่า timeout สำหรับ gateway ทำให้เซิร์ฟเวอร์เกิดการค้าง ในส่วนของแนวทางการแก้ไข ได้ดำเนินการแก้ไขให้แล้วเสร็จโดยการเพิ่ม timeout และตัวดักจับข้อผิดพลาด

แบบที่แนะนำ :
> เช็กให้แล้วครับ ปัญหาเกิดจากระบบรอ response จาก gateway นานเกินไปแล้วไม่ได้ตั้ง timeout ไว้ พอ gateway ไม่ตอบกลับ หน้าเว็บเลยค้าง
>
> ผมแก้ให้เรียบร้อยแล้วครับ โดยใส่ timeout ไว้ 5 วินาที แล้วทำ error handling ไว้ให้ ถ้าเชื่อมต่อไม่สำเร็จจะขึ้นข้อความเตือนให้ผู้ใช้ลองใหม่อีกครั้ง โค้ดเปิด PR ไว้แล้ว รบกวนช่วยเช็กดูให้หน่อยนะครับ

---

### สรุปยอดขายประจำสัปดาห์ส่งหัวหน้า

แบบที่ไม่ควรทำ :
> ตามที่ท่านได้สอบถามเกี่ยวกับรายงานสรุปยอดขายประจำสัปดาห์ ทางเราได้ดำเนินการรวบรวมตัวเลขเสร็จสิ้นแล้ว จึงขอส่งมอบไฟล์ดังกล่าวมาเพื่อโปรดพิจารณา ยิ่งไปกว่านั้น ยอดขายในช่องทางออนไลน์ยังมีการเติบโตขึ้นอย่างมีนัยสำคัญ

แบบที่อ่านแล้วเข้าใจ :
> เสร็จเรียบร้อยครับพี่ ส่งไฟล์สรุปยอดให้ทางเมลแล้วนะครับ สัปดาห์นี้ยอดขายออนไลน์เพิ่มขึ้น 15% จากโปรโมชันเมื่อวันศุกร์ที่ผ่านมา ฝากพี่ช่วยดูไฟล์ให้หน่อยนะครับ ถ้ามีตรงไหนอยากให้ปรับแก้บอกได้เลยครับ

---

### ขอข้อมูลเพิ่มเติม (ระวังเรื่องอารมณ์แฝง)

แบบที่ไม่ควรทำ (แบบ AI) :
> เพื่อที่จะดำเนินการต่อ จำเป็นต้องขอข้อมูลเพิ่มเติมจากท่าน

แบบที่เสี่ยงฟังดูหงุดหงิด (ไม่ควรใช้กับผู้ใหญ่ / ลูกค้า) :
> รบกวนขอข้อมูลเพิ่มหน่อยครับ จะได้เอาไปทำต่อได้ถูก

แบบที่อ่านแล้วเข้าใจและสุภาพ :
> รบกวนขอข้อมูลส่วนนี้เพิ่มเติมหน่อยนะครับ พอดีต้องใช้ประกอบการทำส่วนต่อไปครับ

---

### เมื่อติดปัญหาหรือทำไม่ได้

แบบที่ไม่ควรทำ :
> จากการตรวจสอบพบว่าไม่สามารถดำเนินการได้ เนื่องจากระบบไม่รองรับ

แบบที่อ่านแล้วเข้าใจ (เสนอทางเลือก) :
> พอดีตรงนี้ติดเรื่องระบบนิดหน่อยครับ เลยยังทำตรง ๆ ไม่ได้ เดี๋ยวผมลองปรับเป็นอีกวิธีแทน น่าจะช่วยให้งานเดินต่อได้ครับ

---

### ติดตั้ง package

แบบที่ไม่ควรทำ :
> เพื่อที่จะดำเนินการติดตั้งแพ็กเกจที่จำเป็น ท่านจะต้องเริ่มต้นด้วยการเปิดเทอร์มินัลของท่าน จากนั้นทำการพิมพ์คำสั่งต่อไปนี้ โดยให้แน่ใจว่าท่านมีสิทธิ์ในการเข้าถึงระบบอย่างเพียงพอ

แบบที่อ่านแล้วเข้าใจ :
> เปิด terminal แล้วรันคำสั่งนี้ได้เลยครับ :
> npm install axios
> รอจนขึ้นว่าติดตั้งเสร็จ ก็ใช้งานได้เลยครับ

## 3. สรุปเนื้อหา

### สรุปบทความเรื่อง AI

แบบที่ไม่ควรทำ :
> โดยสรุปแล้ว จากการวิเคราะห์ข้อมูลข้างต้น สามารถสรุปได้ว่าเทคโนโลยีปัญญาประดิษฐ์มีบทบาทสำคัญอย่างยิ่งในการขับเคลื่อนนวัตกรรมในภูมิทัศน์ของอุตสาหกรรมต่าง ๆ อย่างไรก็ตาม ยังคงมีความท้าทายหลายประการที่จำเป็นต้องได้รับการแก้ไข อาทิ ความเป็นส่วนตัวของข้อมูล จริยธรรม ตลอดจนผลกระทบต่อตลาดแรงงาน

แบบที่อ่านแล้วเข้าใจ :
> AI ช่วยเปลี่ยนหลายวงการไปเยอะ แต่ก็ยังมีเรื่องที่ต้องระวัง ทั้งเรื่องข้อมูลส่วนตัว เรื่องจริยธรรม แล้วก็เรื่องที่คนกลัวว่าจะมาแทนงานคน

## 4. เขียน documentation

### อธิบาย function

แบบที่ไม่ควรทำ :
> ฟังก์ชัน calculateTotal มีวัตถุประสงค์เพื่อดำเนินการคำนวณยอดรวมของรายการสินค้าทั้งหมดที่อยู่ในตะกร้าสินค้าของผู้ใช้ โดยรับพารามิเตอร์เป็น array ของ object ที่ประกอบด้วย price และ quantity จากนั้นจะทำการคืนค่าผลลัพธ์เป็นตัวเลขทศนิยมสองตำแหน่ง

แบบที่อ่านแล้วเข้าใจ :
> calculateTotal ใช้คำนวณราคารวมของสินค้าทั้งหมดในตะกร้า
>
> รับ array ของสินค้า (มี price กับ quantity) แล้วคืนราคารวมเป็นทศนิยม 2 ตำแหน่ง
>
> ตัวอย่าง : calculateTotal([{ price: 100, quantity: 2 }]) จะได้ 200.00

---

### อธิบาย config

แบบที่ไม่ควรทำ :
> ในส่วนของ configuration file นั้น มีความจำเป็นอย่างยิ่งที่ผู้ใช้จะต้องทำการกำหนดค่าพารามิเตอร์ต่าง ๆ ให้สอดคล้องกับสภาพแวดล้อมการทำงาน ยิ่งไปกว่านั้น ยังต้องพิจารณาถึงการตั้งค่าความปลอดภัย

แบบที่อ่านแล้วเข้าใจ :
> ตั้งค่าในไฟล์ config ตามสิ่งแวดล้อมที่ใช้งาน
> ถ้าเป็น production ก็ต้องเปิด SSL ด้วย เช่น
> environment: production, ssl: true, port: 443

## 5. เขียนรีวิวหรือความเห็น

### รีวิว library

แบบที่ไม่ควรทำ :
> จากประสบการณ์ในการใช้งาน library ดังกล่าว สามารถกล่าวได้ว่ามีคุณภาพอยู่ในระดับที่น่าพอใจ อย่างไรก็ตาม ยังคงมีข้อจำกัดบางประการที่อาจส่งผลต่อการนำไปประยุกต์ใช้ในโปรเจกต์ขนาดใหญ่ โดยเฉพาะอย่างยิ่งในด้านประสิทธิภาพเมื่อต้องจัดการกับข้อมูลจำนวนมาก

แบบที่อ่านแล้วเข้าใจ :
> Library นี้ใช้ดีนะ สำหรับโปรเจกต์เล็กถึงกลาง แต่ถ้าข้อมูลเยอะจะเริ่มช้า ต้องดูอีกทีว่าเหมาะกับงานที่ทำไหม

## 6. อธิบาย error message

### TypeError

แบบที่ไม่ควรทำ :
> ข้อผิดพลาด TypeError: Cannot read properties of undefined (reading 'map') ที่ปรากฏนั้น บ่งชี้ว่าตัวแปรที่ท่านพยายามเรียกใช้เมธอด map() นั้นมีค่าเป็น undefined ซึ่งหมายความว่ายังไม่ได้รับการกำหนดค่าที่เหมาะสม จำเป็นต้องดำเนินการตรวจสอบว่าข้อมูลถูกส่งมาอย่างถูกต้องก่อนที่จะทำการเรียกใช้เมธอดดังกล่าว

แบบที่อ่านแล้วเข้าใจ :
> Error นี้บอกว่า ตัวแปรที่พยายามใช้ .map() ยังไม่มีค่า (เป็น undefined)
>
> พูดง่าย ๆ ก็คือ ข้อมูลยังมาไม่ถึงตอนที่โค้ดพยายามจะใช้
>
> แก้โดยเช็กก่อนว่าข้อมูลมีค่าหรือยัง เช่น data?.map(...) หรือ if (Array.isArray(data)) { data.map(...) }

## สังเกตความแตกต่าง

ลองอ่านตัวอย่างทั้งหมดด้านบนแล้วจะเห็นว่าแบบ AI มักมีลักษณะร่วมกัน :

- ประโยคยาว ซ้อนหลายชั้น แต่แบบคนเขียนจะสั้น ชัดเจน
- ชอบใช้คำเชื่อมพวก "ยิ่งไปกว่านั้น" "อย่างไรก็ตาม" ซ้ำ ๆ แต่แบบคนเขียนจะใช้แค่ "แล้วก็" "แต่" "พอดี"
- ใส่คำฟุ่มเฟือยเต็มไปหมด "ทำการ" "มีความ" "ดำเนินการ" "ดังกล่าว" แต่แบบคนเขียนจะใช้แค่กริยาตรง ๆ
- สะกดคำทับศัพท์ผิดหรือแปลฝืน ๆ จนงง แต่แบบคนเขียนจะใช้คำภาษาอังกฤษหรือทับศัพท์ที่ถูกต้องตามราชบัณฑิตยสภา
- เรียกผู้อ่านว่า "ท่าน" ใส่ "ฉัน / คุณ" ทุกประโยค แต่แบบคนเขียนจะตัดออกถ้าไม่จำเป็น
- ไม่เว้นวรรคภาษาอังกฤษ ตัวเลข และไม้ยมก (ๆ) ทำให้อ่านยาก แต่แบบคนเขียนจะเว้นวรรค 1 เคาะ ให้อ่านสบายตา
- โทนห่างเหิน เป็นทางการ แต่แบบคนเขียนจะเป็นมิตร เข้าถึงง่าย และยกตัวอย่างให้เห็นภาพเสมอ

## 8. ตัวอย่างการเกลาภาษาแบบคงโครงสร้างและแก่นความหมาย 100% (Structure-Preserved Natural Thai)

### ตัวอย่างที่ 1 : กลยุทธ์ธุรกิจและการแข่งขัน
- **ต้นฉบับ :** "ในโลกของธุรกิจที่เต็มไปด้วยการแข่งขันอย่างเข้มข้น องค์กรต่าง ๆ จำเป็นต้องให้ความสำคัญกับการพัฒนาอย่างต่อเนื่อง เพื่อสร้างความได้เปรียบในการแข่งขันและตอบสนองต่อความต้องการของผู้บริโภคที่เปลี่ยนแปลงอยู่ตลอดเวลา"
- **Natural Thai Rewrite :** "ในโลกธุรกิจที่มีการแข่งขันสูง องค์กรต่าง ๆ ต้องพัฒนาตัวเองอย่างต่อเนื่อง เพื่อสร้างความได้เปรียบในการแข่งขัน และตอบโจทย์ความต้องการของผู้บริโภคที่เปลี่ยนไปตลอดเวลา"
- **จุดที่รักษาไว้ 100% :** องค์กรต่าง ๆ (ไม่เปลี่ยนเป็นบริษัท), สร้างความได้เปรียบ (ไม่เปลี่ยนเป็นรักษา), ความต้องการของผู้บริโภคที่เปลี่ยนไป (ไม่เปลี่ยนเป็นลูกค้าเปลี่ยนใจ)

### ตัวอย่างที่ 2 : นโยบายความปลอดภัยข้อมูลและการยืนยันตัวตน
- **ต้นฉบับ :** "สถาบันการเงินต้องจัดให้มีระบบพิสูจน์และยืนยันตัวตนทางดิจิทัลที่ผ่านการทดสอบความปลอดภัยตามมาตรฐานขั้นต่ำ และห้ามมิให้ส่งต่อข้อมูลชีวมิติของลูกค้าไปยังบุคคลภายนอก เว้นแต่จะได้รับความยินยอมชัดแจ้งเป็นลายลักษณ์อักษร"
- **Natural Thai Rewrite :** "สถาบันการเงินต้องมีระบบพิสูจน์และยืนยันตัวตนทางดิจิทัลที่ผ่านเกณฑ์มาตรฐานความปลอดภัยขั้นต่ำ และห้ามส่งต่อข้อมูลชีวมิติของลูกค้าแก่บุคคลภายนอกเด็ดขาด เว้นแต่ลูกค้าจะให้ความยินยอมเป็นลายลักษณ์อักษรอย่างชัดแจ้ง"
- **จุดที่รักษาไว้ 100% :** ล็อก "ต้อง" และ "ห้าม" (ไม่ลดทอนเป็นควร), สถาบันการเงิน, ข้อมูลชีวมิติ, เงื่อนไขข้อยกเว้นเป็นลายลักษณ์อักษร

> **เป้าหมายหลัก:** สะกดคำทับศัพท์ภาษาอังกฤษให้ถูกต้องตามมาตรฐาน และคงรูปศัพท์เฉพาะทางเทคนิคให้เป็นธรรมชาติสำหรับการทำงานจริงของมนุษย์สาย Tech, Design และ Business

## 2. กริยาภาษาพูดและคำทับศัพท์สายเทคนิค (Developer Tinglish Verbs)

| คำศัพท์ / สำนวน | ความหมายทางเทคนิค | ตัวอย่างการใช้งานจริงของมนุษย์ |
|---|---|---|
| **ยิง API** | Call / Send HTTP Request | *"ลองยิง endpoint นี้ดูยังว่าพ่น response อะไรกลับมา"* |
| **พ่น log / พ่น error** | Print / Output stack trace | *"service พ่น 500 ออกมารัว ๆ เลยพี่"* |
| **ยัด payload / mock** | Pass parameter / Mock data | *"ยัด mock data ก้อนนี้เข้าไปเทสก่อน"* |
| **ตบโค้ด / ตบ layout** | Adjust / Refactor slightly | *"ขอตบ format โค้ดให้ตรง lint แป๊บเดียว"* |
| **โค้ดชน / branch ชน** | Git merge conflict | *"branch ชนกับ main ตรง schema พอดี"* |
| **แตก / บึ้ม / ร่วง** | Service down / Build failed | *"CI แตกเพราะ test ไม่ผ่าน", "Prod ร่วงไป 2 นาที"* |
| **หลุด** | Memory leak / Uncaught edge case | *"เคสนี้หลุดไปถึง prod ได้ไงเนี่ย"* |
| **แกะบั๊ก / ไล่โค้ด** | Debug / Trace stack | *"เดี๋ยวช่วยแกะ log ย้อนหลังให้ครับ"* |
| **ดัน / ปล่อย** | Deploy / Push to environment | *"ดันขึ้น staging เรียบร้อยแล้วครับ"* |
| **ตัน / อืด** | Bottleneck / High latency | *"DB connection pool ตัน หน้าเว็บเลยอืด"* |

## 3. ข้อยกเว้นทางเทคนิคและการรักษาความปลอดภัยของ Syntax (Code Protection Guardrails)

กฎการเว้นวรรค 1 เคาะรอบภาษาอังกฤษและตัวเลข มีผลเฉพาะ **ข้อความบรรยายภาษาไทยทั่วไป** เท่านั้น:

### [ข้อควรระวัง] ข้อห้ามเด็ดขาด (Strict Exceptions):
ห้ามนำกฎการเว้นวรรคภาษาไทยไปใช้ภายในองค์ประกอบทางเทคนิคต่อไปนี้โดยเด็ดขาด:
1. **Code Blocks (```...```):** ห้ามแทรกช่องว่างในโค้ดทุกภาษา
2. **Inline Code (`...`):** ห้ามเว้นวรรค เช่น `get_user_id()` ห้ามแก้เป็น `get _ user _ id ()`
3. **Terminal Commands:** ห้ามเว้นวรรคในคำสั่ง เช่น `npm install --save-dev`
4. **File Paths & URLs:** เช่น `src/controllers/authController.ts`
5. **JSON Keys & Environment Variables:** เช่น `AUTH_SECRET_KEY`
6. **Regular Expressions (Regex):** ห้ามแทรกช่องว่างใน Pattern

## 4. ตารางเปรียบเทียบคำทับศัพท์: ราชบัณฑิตยสภา vs วงการเทคโนโลยี (ORST vs Industry)

| ศัพท์อังกฤษ | ราชบัณฑิตยสภา (ORST) | คำที่ใช้ในวงการเทคโนโลยี | คำแนะนำมาตรฐาน |
|---|---|---|---|
| **Update** | อัปเดต | อัปเดต | **ใช้อัปเดต (ป-ต)** เป็นมาตรฐาน |
| **Function** | ฟังก์ชัน | ฟังก์ชัน | **ใช้ฟังก์ชัน (ก-ช-น-การันต์)** |
| **Email** | อีเมล | อีเมล | **ใช้อีเมล (ล ไม่มีการันต์)** |
| **Server** | เซิร์ฟเวอร์ | เซิร์ฟเวอร์ | **ใช้เซิร์ฟเวอร์** |
| **Digital** | ดิจิทัล | ดิจิทัล | **ใช้ดิจิทัล (ท-ล)** |
| **Application** | แอปพลิเคชัน | แอป / แอปพลิเคชัน | **ใช้แอป (ป) ไม่ใช้ แอพ (พ)** |

## 5. กฎการใช้วรรณยุกต์และการันต์ในคำทับศัพท์ (Tone Mark & Karan Rules)

1. **กฎหลักของราชบัณฑิตยสภา :** คำทับศัพท์ภาษาอังกฤษโดยทั่วไป **ไม่ใส่วรรณยุกต์** (เช่น ลิงก์ ไม่ใช่ ลิ้งค์, คลิก ไม่ใช่ คลิ๊ก, แอป ไม่ใช่ แอพ/แอ๊พ, เซิร์ฟเวอร์ ไม่ใช่ เซิฟเว่อร์, คอมเมนต์ ไม่ใช่ คอมเม้นต์)
2. **ข้อยกเว้นที่บรรจุในพจนานุกรมจนเป็นคำไทย :** เค้ก, คุกกี้, กอล์ฟ, แท็กซี่, ปลั๊ก, โน้ต, ปาร์ตี้, โค้ด
3. **การใช้ทัณฑฆาต (การันต์) :**
   - ฆ่าพยัญชนะตัวที่สองที่ไม่ออกเสียง: โพสต์ (`-st`), สคริปต์ (`-pt`), โปรเจกต์ (`-ct`), การ์ด (`-rd`)
   - พยัญชนะที่ออกเสียงตรงมาตรา **ห้ามใส่การันต์**: อีเมล (ล สะกดตรงตัว), ดิจิทัล (ล สะกดตรงตัว), คลินิก (ก สะกดตรงตัว)

## 6. มาตรฐานการเลือกใช้คำศัพท์เทคนิคและภาษาอังกฤษ 3 ระดับ (The 3-Tier Technical Term Standard)

เพื่อให้ภาษาไทยอ่านลื่นไหล ไม่สะดุดสายตา และคงความแม่นยำทางเทคนิคระดับสากล ให้แบ่งการใช้คำออกเป็น 3 ระดับตามมาตรฐานวงการเทคโนโลยีไทย (สื่อเทคโนโลยีและองค์กรนวัตกรรมชั้นนำของไทย):

### 6.1 Tier 1 : คำสามัญในวงการที่คนไทยคุ้นเคย (Household Tech Terms) -> **ทับศัพท์คำอ่านไทย**
ใช้คำทับศัพท์ภาษาไทยที่สะกดถูกต้องตามมาตรฐาน (ไม่ใส่วรรณยุกต์) เพื่อให้อ่านกลมกลืนกับประโยคภาษาไทย:
- **คำที่ใช้ทับศัพท์ไทย :**
  - อัปเดต, อัปโหลด, ดาวน์โหลด, เซิร์ฟเวอร์, เว็บไซต์, แอป / แอปพลิเคชัน
  - อีเมล, ลิงก์, ฟังก์ชัน, แคช, คอนเซปต์, สคริปต์, โปรเจกต์, โค้ด
  - โพสต์, คอมเมนต์, คลิก, บล็อก, ออนไลน์, ออฟไลน์, ดิจิทัล, ดาต้าเบส (หรือ ฐานข้อมูล)
- *ตัวอย่างการเขียน :*
  - "ลองเคลียร์**แคช**แล้วกด**อัปเดต**หน้า**เว็บไซต์**ใหม่อีกรอบครับ"
  - "วาง**คอนเซปต์**ของ**โปรเจกต์**นี้ไว้ชัดเจนมากครับ"

### 6.2 Tier 2 : ศัพท์เฉพาะทาง สถาปัตยกรรม และโปรโตคอล (Architecture, Protocols & Tools) -> **คงรูปภาษาอังกฤษ**
คงรูปภาษาอังกฤษ (English Alphabet) สำหรับศัพท์เทคนิคเฉพาะทาง ชื่อเครื่องมือ หรือชื่อสถาปัตยกรรม เพื่อป้องกันความกำกวมและง่ายต่อการค้นหาเอกสาร:
- **คำที่คงรูปภาษาอังกฤษ :**
  - API, API Gateway, Microservices, Kubernetes, Redis, Docker, PostgreSQL
  - Payload, Endpoint, Load Balancer, Token, Webhook, Queue, Rate Limit, OAuth2
- *ตัวอย่างการเขียน :*
  - "ปัญหาเกิดจากตัว **API Gateway** ไม่สามารถส่งต่อ **Payload** ไปยัง **Microservices** ได้ครับ"
  - "ระบบแจ้งเตือนผ่าน **Webhook** เกิดปัญหาเชื่อมต่อ **Redis**"

### 6.3 Tier 3 : โค้ด สัญลักษณ์ ตัวแปร และคำสั่ง CLI (Code Identifiers & Syntax) -> **Inline Code (`...`)**
ใช้ Markdown Code Formatting เสมอ ห้ามพิมพ์เป็นคำอ่านไทยเด็ดขาด:
- **ตัวอย่าง :**
  - `authService.restart()`, `npm run build`, `HTTP 500`, `cache-control: no-store`
  - `get_user_id()`, `docker-compose up -d`, `JWT_SECRET_KEY`

## 7. ตารางเปรียบเทียบการเลือกใช้ (Comparison Matrix)

| บริบทข้อความ | [ไม่แนะนำ] ไม่เป็นธรรมชาติ (Unnatural) | [แนะนำ] เป็นธรรมชาติตามมาตรฐาน 3-Tier (Standard Natural) |
|---|---|---|
| **การจัดการระบบแคช** | "ลอง clear cache แล้ว refresh website ดูครับ" *(อังกฤษรกเกินไป)*<br>"ลองล้างที่เก็บข้อมูลชั่วคราว..." *(แปลไทยแข็งทื่อ)* | "ลองเคลียร์**แคช**แล้วรีเฟรชหน้า**เว็บไซต์**ดูครับ" |
| **สถาปัตยกรรมระบบ** | "เอพีไอเกตเวย์ ส่งข้อมูลต่อไปยัง ไมโครเซอร์วิส ไม่ได้" *(ทับศัพท์ไทยจนอ่านยาก)* | "ตัว **API Gateway** ส่งข้อมูลต่อไปยัง **Microservices** ไม่ได้ครับ" |
| **การเรียกใช้งานฟังก์ชัน** | "รันฟังก์ชัน เก็ตยูสเซอร์ไอดี" *(ทับศัพท์โค้ดผิดหลัก)* | "รันฟังก์ชัน `get_user_id()` ได้เลยครับ" |

> [!NOTE]
> **ขอบเขตการบังคับใช้เกณฑ์ทับศัพท์ Tier 1 :** กฎการแปลงเป็นคำทับศัพท์ภาษาไทยมาตรฐาน (เช่น *อัปเดต, เซิร์ฟเวอร์, แคช*) เน้นใช้กับ **งานเขียนบทความ, เอกสารทางการ, คู่มือ, หน้าจอ UI, และการสื่อสารกับลูกค้า/ผู้บริหาร** เพื่อความเป็นมืออาชีพ ส่วนในบทสนทนาแชทด่วนภายในทีมวิศวกร (Dev Slack/Discord) สามารถพิมพ์ภาษาอังกฤษสลับไทย (Tinglish) ตามความคล่องตัวของทีมได้

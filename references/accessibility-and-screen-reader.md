# การเข้าถึงและการรองรับโปรแกรมอ่านหน้าจอ (Accessibility & Screen Reader)

> **เป้าหมายหลัก:** เข้าใจระบบสังเคราะห์เสียงอ่านภาษาไทย (TTS & G2P Architecture - NECTEC PACTT), การแก้ปัญหาคำพ้องรูป (Isolated Homographs), และเกณฑ์ WCAG 2.2 สำหรับภาษาไทย

---

## 1. การแก้ไขคำพ้องรูปโดดเดี่ยวบน UI (Isolated Homograph Disambiguation)

เมื่อชิ้นส่วน UI ไม่มีบริบทแวดล้อม โปรแกรมอ่านหน้าจอ (NVDA, VoiceOver) อาจออกเสียงผิดพลาด ให้ใช้ Semantic Label ช่วย:

| คำพ้องรูป | เสียงอ่านที่ถูกต้อง | การกำกับ ARIA Label ที่แนะนำ |
|---|---|---|
| **สระ** (สระน้ำ) | /สะ/ | `<button type="button"><span class="sr-only">สระว่ายน้ำ</span><span aria-hidden="true">สระ</span></button>` |
| **สระ** (สระผม) | /สะ/ | `<span role="text" aria-label="สระผม">สระ</span>` |
| **สระ** (สระภาษา) | /สะ-หระ/ | `<span role="text" aria-label="สระภาษาไทย">สระ</span>` |
| **เพลา** (กาลเวลา) | /เพ-ลา/ | `<span role="text" aria-label="เวลา">เพลา</span>` |
| **เพลา** (เพลารถ) | /เพลา/ | `<span role="text" aria-label="เพลารถยนต์">เพลา</span>` |

---

## 2. กฎเหล็ก CSS Typography สำหรับภาษาไทย (OpenType Protection)

- **ห้ามใช้ `letter-spacing` (Tracking) กับข้อความภาษาไทย :** เพราะจะทำลายตาราง GPOS ของ OpenType ทำให้สระบนและวรรณยุกต์ลอยหลุดจากพยัญชนะฐาน
- **Line-Height ขั้นต่ำ :** บังคับใช้ `line-height >= 1.5` สำหรับเนื้อหาภาษาไทยเสมอ เพื่อป้องกันวรรณยุกต์ชั้นที่ 2 (เช่น ไม้โท, ไม้ตรี) ถูกตัดขอบกล่องข้อความ
---

## 3. การป้องกันความล้าจาก Emoji และเครื่องหมายวรรคตอน (Emoji & Punctuation Fatigue)
- **หลีกเลี่ยง Emoji ต่อเนื่อง :** โปรแกรมอ่านหน้าจอ (Screen Reader) ภาษาไทยจะอ่านชื่ออิโมจิทุกตัว เช่น "หน้ายิ้มอ้าปากตาโต หน้าพยักหน้า หัวใจสีแดง" การใส่อิโมจิติดกัน 3-5 ตัวทำให้เกิด Cognitive Clutter รุนแรงต่อคนตาบอด
- **การใช้ Microcopy ที่ชัดเจนในตัวเอง :** หลีกเลี่ยงการปล่อยคำพ้องรูปเดี่ยว ๆ บน UI แต่ให้เขียนคำเต็ม เช่น *"สระว่ายน้ำ"* หรือ *"สระภาษาไทย"* เพื่อช่วยเหลือทั้งผู้บกพร่องทางการมองเห็นและผู้มีความบกพร่องด้านการเรียนรู้ (Cognitive Disability)

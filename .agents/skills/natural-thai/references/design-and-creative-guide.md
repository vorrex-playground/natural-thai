# คู่มือการสื่อสารสายงานออกแบบและครีเอทีฟ (Design & Creative Communication Guide)

เอกสารนี้รวบรวมมาตรฐานการสื่อสาร ระดับภาษา คำศัพท์เฉพาะทาง และแนวทางสนทนาสำหรับสายงาน UX/UI Design, Product Design, Graphic Design, Brand Identity และงานสื่อสิ่งพิมพ์/ดิจิทัลในประเทศไทย

---

## 1. วัฒนธรรมการสื่อสารในสายงานดีไซน์ (Design Communication Culture)

1. **การใช้คำศัพท์เทคนิคภาษาอังกฤษ (Code-Switching) :** ในวงการดีไซน์ คนไทยใช้คำทับศัพท์ภาษาอังกฤษตามเครื่องมือ (Figma, Adobe) และทฤษฎีสากลเสมอ **ห้ามแปลศัพท์เทคนิคเป็นภาษาไทยตรงตัวเด็ดขาด** (เช่น อย่าแปล Wireframe เป็น "โครงลวด" หรือแปล Key Visual เป็น "ภาพหลักแห่งสายตา")
2. **การอธิบายงานด้วยเหตุผลและข้อมูล (Objective & Rationale) :** ดีไซน์คือการแก้ปัญหาให้ผู้ใช้และตอบโจทย์ธุรกิจ การอธิบายงานต้องอิงหลักการ (เช่น Visual Hierarchy, Cognitive Load, WCAG Contrast, Conversion) ไม่พูดลอย ๆ แค่ว่า "สวย" หรือ "เพราะชอบ"
3. **การให้และรับฟีดแบ็กอย่างสร้างสรรค์ (Constructive Critique) :** แยก "ตัวบุคคล" ออกจาก "ชิ้นงาน" ชี้ให้เห็นผลกระทบต่อผู้ใช้งาน และเสนอทางเลือกที่เป็นรูปธรรม

---

## 2. ตารางคำศัพท์เฉพาะทางสายดีไซน์ (Design Glossary)

| คำภาษาอังกฤษ | คำแปล AI ที่ห้ามใช้ | ภาษาคนดีไซน์ใช้จริง | บริบทการใช้งาน |
|---|---|---|---|
| **Wireframe** | โครงร่างลวด / โครงสายลวด | **Wireframe / โครงหน้าจอ Low-Fi** | โครงสร้าง Layout ก่อนลงรายละเอียด |
| **Mockup** | แบบจำลองภาพนิ่ง | **Mockup / หน้าจอ Hi-Fi ดีไซน์เสร็จ** | หน้าจอจำลองที่ใส่สีและรูปภาพสมบูรณ์ |
| **Prototype** | ชิ้นงานต้นแบบ | **Prototype / ตัวคลิกได้** | ไฟล์ที่ผูก Interaction ให้กดทดสอบได้ |
| **User Flow** | การไหลของผู้ใช้ | **User Flow / Flow การใช้งาน** | ลำดับขั้นตอนการใช้งานระบบ |
| **Design System** | ระบบการออกแบบ | **Design System / ดีไซน์ซิสเต็ม** | โครงสร้าง Component, Token, Guideline รวม |
| **Component** | ส่วนประกอบ | **Component (เช่น Button, Modal, Card)** | ชิ้นส่วน UI สำเร็จรูปที่นำมาประกอบ |
| **State (UI)** | รัฐของอินเทอร์เฟซ | **State (Default, Hover, Active, Disabled, Error)** | สถานะต่าง ๆ ของปุ่มหรือฟอร์ม |
| **Usability Test** | การทดสอบความสามารถในการใช้งาน | **Usability Test / ทำ UT / เทสต์กับ User** | การนำ Prototype ไปทดสอบกับผู้ใช้จริง |
| **Pain Point** | จุดเจ็บปวด | **Pain point / ปัญหาจุดติดขัดของผู้ใช้** | ปัญหาที่ผู้ใช้เจอในการใช้งาน |
| **User Journey** | การเดินทางของผู้ใช้ | **User Journey / ประสบการณ์ผู้ใช้** | เส้นทางประสบการณ์ผู้ใช้ตั้งแต่ต้นจนจบ |
| **Edge Case** | ปัญหาริมขอบ | **Edge case / เคสไม่ปกติ / เคสพิเศษ** | เคสที่เกิดไม่บ่อยแต่ต้องดัก เช่น เน็ตหลุด |
| **Accessibility (a11y)** | การเข้าถึงได้ | **Accessibility / A11y / เกณฑ์ WCAG** | เกณฑ์การเข้าถึง เช่น Contrast Ratio |
| **Microcopy** | สำเนาขนาดย่อม | **Microcopy / UX Writing / ข้อความบน UI** | ข้อความบนปุ่มกด Error text และ Tooltip |
| **Empty State** | รัฐว่างเปล่า | **Empty state / หน้าจอตอนยังไม่มีข้อมูล** | เช่น ตะกร้าสินค้าว่าง ยังไม่มีรายการแจ้งเตือน |
| **Dev Handover** | การส่งมอบงานพัฒนา | **Dev Handover / Handoff ให้เดฟ** | การส่ง Spec และ Asset ให้โปรแกรมเมอร์ |
| **Visual Hierarchy** | ลำดับชั้นแห่งสายตา | **Visual Hierarchy / การจัดลำดับสายตา** | การเน้นความเด่น-รองของข้อมูล |
| **Cognitive Load** | ภาระทางปัญญา | **Cognitive load / ความซับซ้อนของข้อมูล** | ภาระการประมวลผลของผู้ใช้ |
| **Mood Board** | กระดานอารมณ์ | **Mood board / มู้ดบอร์ด** | การรวบรวมโทนภาพและสไตล์ก่อนเริ่มงาน |
| **Key Visual (KV)** | ภาพหลักแห่งสายตา | **Key Visual / KV / ภาพแกนหลักแคมเปญ** | ภาพหลักที่ใช้ต่อยอดเป็นสื่อต่าง ๆ |
| **CI / VI** | อัตลักษณ์องค์กร | **CI / VI / Brand Guideline / คู่มือแบรนด์** | คู่มือการใช้โลโก้ สี ฟอนต์ประจำแบรนด์ |
| **Color Palette** | จานสีผสม | **Color Palette / ชุดสี / โทนสีประจำแบรนด์** | กลุ่มสีที่กำหนดใช้ในงาน |
| **Bleed (Print)** | การมีเลือดออก | **ระยะตัดตก / Bleed (ปกติเผื่อ 3 มม.)** | ขอบสีที่ขยายเกินเส้นตัดกันขอบขาว |
| **Safe Margin** | เขตปลอดภัย | **ระยะปลอดภัย / Safe Zone / Margin** | ระยะเว้นจากขอบตัดไม่ให้ตัวหนังสือชิดเกินไป |
| **Create Outline** | สร้างเส้นขอบนอก | **Create Outline / แปลงฟอนต์เป็นเวกเตอร์** | การแปลงฟอนต์ก่อนส่งโรงพิมพ์ |
| **Die-cut** | การตัดให้ตาย | **ไดคัท (Die-cut) / ลบพื้นหลัง / เจาะขอบ** | การตัดแต่งขอบรูปทรง |

## 3. รูปแบบการสื่อสารและตัวอย่างสถานการณ์จริง (Scenarios & Examples)

### สถานการณ์ที่ 1 : อธิบายเหตุผลการดีไซน์ (Design Rationale) ต่อ PM / ลูกค้า
- **แบบที่ไม่ควรทำ (แบบ AI) :** "ข้าพเจ้าขอแจ้งว่าจากการวิเคราะห์การเดินทางของผู้ใช้งาน พบว่าจุดเจ็บปวดอันยิ่งใหญ่คือผู้ใช้มีภาระทางปัญญาที่ล้นหลาม ส่งผลให้อัตราการตกหล่นพุ่งสูงขึ้น ข้าพเจ้าจึงได้สร้างสรรค์โครงร่างลวดใหม่เพื่อปลดล็อกประสบการณ์ไร้รอยต่อ"
- **แบบที่แนะนำ :** "ขอสรุป Rationale ในการ Redesign หน้า Checkout Flow ใหม่ครับ:

จากข้อมูลล่าสุด เราพบ Drop-off rate สูงถึง 42% ในขั้นตอน Checkout โดย Insight จากการทำ Usability Test ชี้ว่า Form เดิมรวมทุกอย่างไว้ในหน้าเดียว ทำให้เกิด Cognitive overload ผู้ใช้รู้สึกว่าขั้นตอนยาวเกินไปและสับสนเรื่องค่าส่ง

ดีไซน์ใหม่จึงปรับเป็น Multi-step Checkout (3 ขั้นตอนสั้น ๆ: ข้อมูลจัดส่ง -> วิธีชำระเงิน -> สรุปคำสั่งซื้อ):
1. Step Indicator ด้านบน : ช่วยให้ User รู้ว่าอยู่ตรงไหนและเหลืออีกกี่ขั้นตอน
2. Auto-fill ที่อยู่ : ดึงข้อมูลเดิมให้อัตโนมัติ ลดการพิมพ์บนมือถือ
3. Sticky Order Summary : แสดงยอดสุทธิและค่าส่งชัดเจนตลอดเวลา

คาดว่า Flow นี้จะช่วยลด Friction และดัน Conversion Rate ให้กลับมาตามเป้าครับ"

---

### สถานการณ์ที่ 2 : ให้ฟีดแบ็กงานในห้องตรวจแบบ (Design Critique)
- **แบบที่ไม่ควรทำ (แบบ AI) :** "ข้าพเจ้ารู้สึกว่าหน้าต่างนี้ยังขาดความกลมกลืนทางสุนทรียศาสตร์ การจัดวางดูเหมือนยังไม่ส่งเสียงสะท้อนถึงหัวใจผู้ใช้ สีสันดูไร้ชีวิตชีวา ควรเพิ่มมนต์เสน่ห์อันเจิดจรัสยิ่งขึ้น"
- **แบบที่แนะนำ :** "ภาพรวม Visual Hierarchy ของหน้า Search ทำออกมาคลีนดีมากครับ ขอแชร์ Feedback เพิ่มเติม 3 จุดเพื่อเสริม Usability ครับ:

1. ปุ่ม Filter บน Mobile : ตอนนี้ไอคอนขนาด 24x24 px อาจจะเล็กไปสำหรับ Tap target (ตามเกณฑ์ Accessibility ควรอยู่ที่ 44x44 px) เสนอปรับเป็น Floating Bar ด้านล่างเพื่อให้กดง่ายด้วยมือเดียว
2. Active State ของ Filter Tag : เมื่อผู้ใช้กดเลือกแล้ว สียังไม่ต่างจาก Default state ชัดเจน แนะนำเปลี่ยนพื้นหลัง Tag เป็น Primary Color เพื่อให้ User รู้ว่ามี Filter ไหนทำงานอยู่บ้าง
3. Empty State : ถ้าค้นหาแล้วไม่เจอผลลัพธ์ ตอนนี้หน้าจอว่างเปล่า แนะนำใส่ Microcopy แนะนำคำค้นหายอดนิยม หรือมีปุ่ม 'ล้างตัวกรองทั้งหมด' เพื่อไม่ให้ User ค้างอยู่หน้านั้นครับ"

---

### สถานการณ์ที่ 3 : ส่งมอบงานดีไซน์ให้ Developer (Dev Handover)
- **แบบที่ไม่ควรทำ (แบบ AI) :** "กราบเรียนทีมวิศวกร ชิ้นงานต้นแบบได้ถูกจัดเตรียมไว้อย่างสมบูรณ์แบบแล้ว ขอท่านโปรดนำชิ้นส่วนไปประกอบสร้างเป็นแอปพลิเคชันตามที่แสดงไว้ในภาพ"
- **แบบที่แนะนำ :** "ส่ง Handover หน้า Product Detail Page (PDP) Rev.3 ครับ

สิ่งที่อัปเดตและจุดที่ต้องระวังในการขึ้น Component:
1. Design Tokens & Spacing : ใช้ Auto Layout ทั้งหมด อิงตาม 8pt Spacing Token (space-2 = 8px, space-4 = 16px, space-6 = 24px) และ Color Token ใช้ชื่อตามดีไซน์ซิสเต็ม (เช่น text-primary, bg-surface-elevated)
2. Component States (ดู Frame ย่อยด้านข้าง) : ปุ่ม Add to Cart มีครบทั้ง Default, Hover, Loading (Spinner), Disabled (Out of stock)
3. Breakpoints : Mobile 375px (Image Gallery เป็น Swipe Carousel) และ Desktop 1440px+ (Image Gallery เป็น 2-Column Sticky)
4. Edge Cases : ชื่อสินค้ายาวเกิน 2 บรรทัดให้ทำ Truncate ท้ายด้วย '...' และกรณีรูปโหลดไม่ขึ้น มี Placeholder Asset เตรียมไว้ให้ในโฟลเดอร์ Assets แล้วครับ

มีข้อสงสัยจุดไหน Tag ถามใน Figma หรือทักช่อง dev-design-sync ได้เลยครับ"

---

### สถานการณ์ที่ 4 : นำเสนอ Mood Board และทิศทางสร้างสรรค์ให้ลูกค้า (Brand Direction)
- **แบบที่ไม่ควรทำ (แบบ AI) :** "เรียน ลูกค้าผู้มีอุปการคุณ ทางเราขอส่งกระดานอารมณ์สำหรับภาพหลักแห่งสายตาของแบรนด์ท่าน เราได้ผสมผสานอัตลักษณ์ให้เข้ากับความล้ำสมัยในยุคดิจิทัล หวังว่าท่านจะมีความสุขกับทัศนียภาพที่ปรากฏ"
- **แบบที่แนะนำ :** "สวัสดีครับทีม [ชื่อแบรนด์]

ทางทีมขอส่ง Mood Board & Creative Direction สำหรับแคมเปญ Rebranding เพื่อให้ทีมร่วมรีวิวก่อนเริ่มดราฟต์ Key Visual ชิ้นแรกครับ

ทิศทางที่นำเสนอ: 'Modern Minimal with Warmth'
- Core Concept : สะท้อนภาพลักษณ์แบรนด์ที่น่าเชื่อถือ เข้าถึงง่าย แต่ยังคงความพรีเมียม เหมาะกับกลุ่มคนรุ่นใหม่ (First Jobber & Millennial)
- Visual Style : ใช้เส้นสายเรียบง่าย (Clean Geometry) ผสมผสานกับการจัดวาง Typography แบบ Editorial เพื่อความโปร่งสบายตา
- Color Palette : Warm Earth Tone (Beige, Warm Sand) เป็นพื้นหลัง เพื่อความอบอุ่น เป็นมิตร และ Forest Green เป็นสี Primary Accent สื่อถึงความยั่งยืนและความมั่นคง
- Photography Direction : เน้นภาพถ่ายแสงธรรมชาติ ท่าทางของแบบดูเป็นธรรมชาติ ไม่เกร็งหรือโพสทางการจนเกินไป

รบกวนทีมดู Mood & Tone ในสไลด์แนบ หากเห็นตรงกัน ทางทีมจะเริ่มพัฒนา Master Key Visual 2 ออปชันให้ตรวจในรอบถัดไป (วันพฤหัสบดีนี้) ครับ"

---

### สถานการณ์ที่ 5 : เจรจารอบการแก้งาน (Revision Scope) กับลูกค้าอย่างมืออาชีพ
- **แบบที่ไม่ควรทำ (แบบ AI) :** "ท่านลูกค้าที่เคารพ ทางเราไม่สามารถแก้ไขงานตามที่ท่านร้องขอได้ เนื่องจากท่านขอแก้ไขเกินจำนวนครั้งที่กำหนดไว้ในสัญญาแล้ว หากท่านต้องการแก้ต่อ กรุณาจ่ายเงินเพิ่ม มิฉะนั้นเราจะหยุดทำงานทันที"
- **แบบที่แนะนำ :** "สวัสดีครับคุณ [ชื่อลูกค้า]

ทางทีมได้รับฟีดแบ็กล่าสุดเรื่องการขอปรับเปลี่ยน Concept ของ Key Visual และการเปลี่ยน Layout ทั้งหมดเรียบร้อยแล้วครับ

ทีมขออนุญาตเรียนชี้แจงเบื้องต้นว่า ตอนนี้งานอยู่ในขั้นตอน Final Revision (รอบแก้ไขเก็บรายละเอียดรอบที่ 3 ตาม Scope of Work) ซึ่งผ่านการอนุมัติ Mood & Tone และ Concept หลักร่วมกันมาแล้วในรอบแรกครับ

เพื่อให้งานเสร็จทันตามกำหนดเปิดตัวแคมเปญในวันที่ [ระบุวันที่] ทีมขอเสนอ 2 แนวทางดังนี้ครับ:
- แนวทางที่ 1 (แนะนำเพื่อให้ทันวัน Launch) : ปรับจูนองค์ประกอบและสีใน Layout ปัจจุบันตามข้อเสนอแนะของคุณ [ชื่อลูกค้า] โดยคงโครงสร้างหลักไว้ ซึ่งตรงนี้ทีมดำเนินการให้ได้ทันทีภายในรอบงานเดิมและส่งไฟล์ Final ได้ภายในวันพรุ่งนี้ครับ
- แนวทางที่ 2 (ขึ้น Concept ใหม่) : หากต้องการปรับเปลี่ยนโครงสร้างและวาง Concept ใหม่ทั้งหมด ทางทีมยินดีเปิด Job เพิ่มเติมสำหรับแบบใหม่ โดยจะมีค่าบริการส่วนเพิ่มและขยาย Timeline ส่งงานออกไปประมาณ 3-5 วันทำการครับ

คุณ [ชื่อลูกค้า] สะดวกพิจารณาเป็นแนวทางไหนดีครับ เพื่อให้ทีมเริ่มงานต่อได้ตรงจุดครับผม"

### สถานการณ์ที่ 6 : ส่งไฟล์ Artwork ให้โรงพิมพ์ (Pre-flight & Print Specs)
- **แบบที่ไม่ควรทำ (แบบ AI) :** "เรียน โรงพิมพ์ ข้าพเจ้าได้แนบงานศิลปะมาพร้อมจดหมายนี้ ข้าพเจ้าได้สร้างเส้นขอบนอกให้กับตัวอักษรแล้ว และเผื่อการมีเลือดออกของสีไว้ 3 มิลลิเมตร พร้อมใช้ระบบสีผสม 4 สี ขอท่านโปรดปั๊มงานศิลปะนี้ลงบนกระดาษด้วยความประณีต"
- **แบบที่แนะนำ :** "สวัสดีครับทีมงาน [ชื่อโรงพิมพ์]

ขอส่งไฟล์ Artwork สำหรับสั่งพิมพ์โบรชัวร์ขนาด A4 พับ 3 (Tri-fold Brochure) จำนวน 5,000 เล่มครับ

รายละเอียดการจัดเตรียมไฟล์ (Pre-flight Specs):
1. ไฟล์ที่แนบ : PDF/X-1a (Press Quality) พร้อมไฟล์ .AI แยก Folder Links & Fonts
2. ฟอนต์ : Create Outline ตัวอักษรทั้งหมด 100% เรียบร้อยแล้วครับ
3. ระบบสี : CMYK ทุกหน้า (ไม่มีค่าสี RGB / ไม่มี Spot Color หลุดครับ)
4. ความละเอียดรูปภาพ : 300 DPI ทุกภาพ
5. ระยะตัดตกและระยะปลอดภัย : เผื่อ Bleed รอบด้าน 3 mm. และตั้ง Safe Margin ด้านใน 5 mm. จากขอบพับและขอบตัด
6. งานหลังพิมพ์ : เคลือบด้าน (Matt OPP) หน้า-หลัง + สปอตยูวี (Spot UV) เฉพาะบริเวณโลโก้หน้าปก (แยกเลเยอร์ Spot UV เป็นสีดำ K:100 ให้ในไฟล์แล้วครับ)

รบกวนทางโรงพิมพ์เช็กไฟล์และส่ง Digital Proof (พรูฟดิจิทัล) ให้ตรวจความถูกต้องของสีก่อนสั่งรันผลิตจริงด้วยนะครับ ขอบคุณครับ"
